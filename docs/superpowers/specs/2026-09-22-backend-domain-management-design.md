# 后端域名管理设计

状态：方案范围已确认，详细设计待评审；尚未实现或修改线上配置。

## 目标与边界

在后端仓库提供一条命令，为现有宝塔 Nginx + Supervisor 部署新增、替换或停用后端域名，并可选上传或更新证书。不修改玩家端、管理端，不新增后台页面，不修改 DNS，不申请或自动续签证书，不修改第三方回调，不迁移数据库。

HTTP 始终启用，不强制跳转 HTTPS。提供有效证书及私钥，或显式指定已有匹配证书时，同时启用 HTTPS。没有证书时只声明 HTTP 可用，不使用其他域名的默认证书冒充 HTTPS 支持。所有远程操作只允许 AGENTS.md 授权的测试、正式服务器。

## 已确认的现状

- 线上使用宝塔 Nginx、Supervisor；旧 Docker 部署说明不是本方案依据。
- API 和 Realtime 的本机端口分别为 8080、8081。
- API 白名单是带协议的 Origin，Realtime 白名单是主机及可选端口模式，启动时读取。
- 现有统一部署入口会上传环境文件并覆盖服务器环境配置，直接修改该文件会被后续发布覆盖。
- 现有 Nginx 文件可能包含多个域名、HTTP 与 HTTPS 块以及独立前端站点，不能通过全局文本替换接管。

## 命令操作契约

入口拟为 `scripts/domains.sh`，显式指定 `staging` 或 `production`，不接受任意远程主机。下面使用占位域名，命令尚未实现。

```sh
./scripts/domains.sh production add api.example.com
./scripts/domains.sh production add api.example.com --cert /local/fullchain.pem --key /local/privkey.pem
./scripts/domains.sh production certificate api.example.com --cert /local/fullchain.pem --key /local/privkey.pem
./scripts/domains.sh production replace api-old.example.com api-new.example.com
./scripts/domains.sh production remove api-old.example.com
./scripts/domains.sh production list
```

- `add` 为增量操作，不移除旧域名。重复相同请求无变化，不重复重载或重启。
- `certificate` 替换证书并保留 HTTP；证书和私钥必须成对提供。已有证书复用通过显式路径参数实现，不盲目遍历或选择其他站点证书。
- `replace` 先新增并验证新域名，再删除旧域名。旧域名证书不自动复制给新域名。替换请求支持和新增相同的证书选项；没有证书的新域名仅启用 HTTP。
- `remove` 只操作本工具管理的域名，移除配置但保留受限访问的回滚材料，不删除用户原始证书文件。
- 提供 `--dry-run`，输出变更摘要及检查结果，不改远程文件、不上传私钥、不重载服务。
- `list` 分别显示 HTTP、HTTPS 配置状态和证书到期时间，区分配置已启用与最近一次检查结果。

## 域名与 Origin 分开管理

后端域名用于 Nginx 路由；浏览器页面来源用于 CORS 和 WebSocket Origin 校验，两者不能混为一谈。

新增后端域名默认保留全部既有 Origin。允许显式传入重复的 `--allow-origin http://web.example.com`、`--allow-origin https://web.example.com`，只增加指定来源，不自动放行所有来源，也不推导不存在的子域名。Realtime 从这些完整 Origin 提取主机及端口，沿用当前库的校验语义，不宣称它提供与 CORS 一样的协议隔离。

管理状态记录每条来源的归属；删除一个域名不得撤销其他域名仍引用的来源或原有环境配置中的来源。只变更后端路由且没有 Origin 变化时，不重启 API 或 Realtime。

## 持久化与部署兼容

管理状态存放在 `/etc/block-beast/domains/`，采用版本化 JSON，包含域名、可选证书引用、显式允许的来源和操作版本；不把私钥写入 JSON。

新增独立的可选 Origin 配置文件，由 API、Realtime 启动时读取并与原有环境白名单合并去重。文件路径具有明确配置项并记录到 `.env.example`；未启用时保持当前行为，显式配置但文件缺失或损坏时启动失败，不静默扩大权限。部署入口确保受管服务器持续引用此独立文件，不依赖开发机环境文件保留新增来源。

域名管理和部署共用远端排他锁，避免部署与白名单变更相互覆盖。文件不放在发布目录中，部署包不得覆盖它们。普通应用运行账号只获得必需的读取权限；只有运维执行器能写入配置和读取证书私钥。

## Nginx 与证书

每个受管域名生成独立且有固定前缀的配置文件。`/v1/ws` 精确路由至本机 Realtime，其他路径转发本机 API；保留 Host、客户端地址、正确的转发协议和 WebSocket Upgrade 头。沿用上传大小、代理超时等现有必要限制。

HTTP 监听 80；有有效证书才生成 443 TLS 块。输入只允许规范化的明确 DNS 主机名；拒绝 URL、端口、路径、通配符、换行及配置注入字符。涉及现有非受管 server_name 的冲突直接报错，避免 Nginx 忽略重复配置造成假成功。

首次接管既有域名是独立的显式导入步骤：只修改经过校验的后端站点配置，保留同一 server 块的其他域名、原证书及代理指令；复杂或无法可靠解析的配置拒绝自动接管。绝不修改前端站点。操作前展示差异并保存原文件，后续 remove/replace 仅管理已接管的域名。

上传证书在隔离目录检查 PEM、有效期、SAN 域名匹配、证书链以及私钥匹配；不接受需要交互输入密码的加密私钥。远端目录权限 0700、私钥 0600，命令参数和日志不含私钥正文。更新证书使用新版本文件，加载验证通过后才标记当前版本。上传的临时材料在成功或失败后清理，回滚副本保持相同访问限制。

## 应用与回滚

1. 固定环境目标，校验输入和依赖，获取锁，检查现有状态与冲突。
2. 在独立暂存区生成候选配置、证书和 Origin 文件，保存受影响文件的原始内容、权限及原先是否存在。
3. 校验证书及完整候选 Nginx 配置；配置变更只覆盖本次受影响文件。
4. 应用配置，执行 Nginx 检查并平滑重载；仅 Origin 有变化时重启 API、Realtime，不重启 Worker、数据库和消息服务。
5. 执行有超时、有限重试的验收。成功后提交管理状态和不含秘密的操作记录。
6. 任一步骤失败恢复本次配置、证书引用和 Origin 文件，并重新加载原配置。恢复后再次检查服务；回滚失败必须明确报错，保留恢复材料，不显示成功。

多文件与多进程不是真正事务，通过操作日志和阶段标记实现失败恢复。启动下一次操作时检查未完成记录，先恢复或要求处理明确冲突，不能直接覆盖。replace 的新入口验证成功前不得移除旧入口。

## 验收与实际限制

远程访问仅连接授权服务器 IP；域名用于 Host/SNI，健康检查固定连接授权地址，不跟随重定向到未知服务器。DNS 由用户处理，脚本检查服务器侧路由不等于证明公网 DNS 已传播或域名在所有网络可访问。

- HTTP：经 Nginx 请求 API 健康与就绪接口，检查状态及预期响应，防止误命中默认站点。
- HTTPS：使用指定域名 SNI 验证证书和同样的 API 路由，不通过跳过证书检查制造成功。
- Origin：分别验证允许来源和拒绝来源的预检请求；使用现有真实行为构建测试。
- WebSocket：未认证握手返回 401 仅证明路由可达，不宣称端到端握手成功。自动化集成测试覆盖有效会话握手及不允许来源拒绝；线上完整握手验收需安全提供测试会话，缺少会话时明确标记未执行。
- 修改 Origin 会短暂重启 API、Realtime，现有 WebSocket 需要重连；不承诺零中断。
- 全局存在其他 TLS 默认站点时，无证书域名的 443 可能收到默认站点证书；列表必须标记本域名 HTTPS 未配置。

## 测试与交付

本地测试使用临时目录、临时证书及替身命令，不连接任何未授权地址。覆盖 HTTP-only、TLS 新增和续换、证书不匹配或过期、重复执行、Origin 合并与归属、非受管冲突、替换顺序、权限、并发锁、Nginx 检查失败、重启失败、验收失败和回滚失败。

部署回归测试覆盖上传新环境文件后独立白名单仍然生效。执行修改文件 gofmt、相关测试和 `go test ./...`；新增配置项补充示例与操作文档。测试环境集成验收使用专用测试域名；没有域名或证书时不冒用正式入口。

交付包括命令入口、远端执行器、后端配置加载支持、部署兼容、测试及使用文档。真实域名与证书由用户在执行时提供，不提交到仓库。本设计阶段不执行生产变更。
