# LULU 后端协议与部署

本文面向后端开发和运维。玩家端、管理端的全部调用流程、请求示例、权限和错误处理统一见 [前端接入文档](frontend-api.md#lulu-彩石充提)，接口 schema 见 [OpenAPI](openapi.yaml)。

## 部署与配置存储

1. 停止 lulu-worker，停止 API 后按顺序应用迁移至 0074，再更新 API 和专用进程。0071 会暂停通道。0073 移除 matched 状态；如果存在历史 matched 订单会报错停止，须先在旧版本核对处理，迁移不会自动修改余额或删除订单。
2. 在服务器配置 LULU_CONFIG_ENCRYPTION_KEY：32 随机字节的 Base64，可用 openssl rand -base64 32 生成，禁止写入仓库。API 和 lulu-worker 使用同一主密钥，备份数据库时须安全备份主密钥。
3. 管理员按前端文档完成基础配置、短信登录、启用通道。
4. 运行 scripts/deploy-production.sh，默认构建并启动 API、worker、realtime、lulu-worker。lulu-worker 已并入 compose.production.yaml，不需要额外 overlay 或 profile；手动部署也可使用 docker compose --env-file .env.production -f compose.production.yaml up -d lulu-worker。通道未启用时常驻待命，已启用时会自动处理已审核付款。

运行配置和凭据存于数据库，不读取旧 Token 文件和旧收付环境变量。Token 由短信登录获取；Token 和协议密钥采用 AES-256-GCM 分用途加密。审计仅记录公开配置和凭据变更标志。

worker 每轮读取并解密配置，默认 5 秒周期，请求耗时会延迟应用。派发前复核配置版本，旧快照不能在更新后派发新付款；登录更新凭据后无需重启。停用不撤销已派发付款或已识别到账义务。

## 资金与恢复

上分的余额、订单、流水归属、账本和 outbox 同事务提交。下分先冻结，审核后排队，持久化 sending 后调用上游。明确成功扣冻结额，发送前明确失败解冻，发送后不确定结果保持冻结并转 unknown。持独占锁启动时将遗留 sending 转 unknown，不自动重发，由人工核对处理。

## 协议边界与验证

适配器移植了原项目的 GET 到账、账号查询和加密转赠协议，使用标准库 AES-CBC +
HMAC 校验报文，TLS 校验证书、拒绝重定向，不自动重试转赠。
不启动旧 Python 服务，不暴露无鉴权内部上分入口。

当前参考代码没有可确认的服务商唯一流水号和转赠幂等键，故到账使用
收款 UID+转出 UID+毫秒时间+数量+物品 ID 的 SHA-256 指纹。
同毫秒完全相同的多笔记录会保守去重，可能少记，不能据此承诺绝对唯一。
应在联调时确认服务商真正流水 ID 和可靠出账查询，再升级此规则。
目前 unknown 通过人工核对闭环，不通过时间/金额猜测出账成功。

到账分页每页 100 条，最多 1000 页；出现重复页、坏报文或分页超限报错，保留水位。
每轮回看水位前 10 分钟；长期掉线从旧水位继续分页，而非只看最新 100 条。
超出回看范围才延迟出现的旧记录需要运维对账，不保证自动发现。
首查从显式时间起点采集，不把第一笔新转入静默当作基线忽略。

已知上游协议只基于本地参考源码；本地测试不执行真实登录和转赠。
上线前需要配置及真实小额联调，核实 Token 有效性、接口返回、收款库存、
流水唯一性和失败语义。所有远程操作仍遵守仓库唯一授权服务器约束。

## 账本与验证命令

`lulu_deposit` 为充值，`lulu_withdrawal_freeze` 为冻结，
`lulu_withdrawal_debit` 为最终下分，`lulu_withdrawal_unfreeze` 为解冻。
看板按币种统计充值/最终下分，不将冻结计为下分，不将 ORIGIN_STONE 与其他币种相加。

```sh
go test ./...
# 指向已应用迁移的隔离测试库，禁止使用生产库
POSTGRES_TEST_DSN='本地测试库DSN' go test -race ./internal/application/lulu -count=1
```

0074 将噜噜通道改用既有 ORIGIN_STONE（精度 3），每彩石入账 1000 最小单位；订单及上游数量仍为整数彩石。迁移暂停通道并删除空的 LULU 钱包与币种。若存在在途订单、LULU 余额或账本历史则停止迁移，不自动删除或重写资金记录。其他配置或资金表仍引用 LULU 时外键同样阻止删除，需要先核对处理。源石余额与精度保持原样。必须停止旧 API 和 lulu-worker 后迁移，再部署新版本并启用通道。

每轮采集先补匹配数据库中已有的未认领流水，每轮最多 100 笔符合订单窗口的记录，不受上游 10 分钟回看水位限制。关联、余额和账本继续使用原幂等事务。
