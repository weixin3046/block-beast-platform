本次仅修改后端仓库。未连接服务器、未部署、未改现有业务数据库或其他前后台项目。

## 已落地

| 迁移 | 内容 |

| 0045 | 积分/体力流水搬入统一账本，保存原 ID/金额/时间/备注/操作人；区分可用与冻结变化，同事务生成钱包 outbox；移除旧流水表及已停用签到表。 |

| 0048 | 活动配置版本及领取/抽奖/排行榜发奖快照；排行榜启用奖励区间不得重叠；登记有序执行完毕的初始化迁移基线。 |

币种关联使用唯一且不可变的 `currencies.code` 外键，而非在每张业务表重复增加可独立写入的 `currency_id`。币种目录仍有 UUID 主键。不同币种之间不合并余额、不换算汇率。

平台注册精度：USDT 6 位；POINTS、JADE、ORIGIN_STONE 3 位；四种体力 0 位。自定义币种创建时明确指定 0–18 位，未登记币种不再默认为 0 位。已登记币种之间，任务累计/奖励、转盘消耗/奖励仍可自由搭配。

API 新增：

- `GET /v1/currencies`：玩家查询已启用币种。
- `GET/POST /v1/admin/currencies`、`PUT /v1/admin/currencies/{code}`：仅 admin 管理目录，更新校验版本。
- `GET /v1/users/me/ledger`：本人全部币种流水，支持 currency、limit、cursor；返回后端格式化金额及余额，历史冻结快照可能为 null。
- 全部钱包余额接口新增 decimals、available、frozen。旧积分/体力流水接口保留路径，但改为统一账本查询。

## 数据语义

- `amount_minor` 是业务发生额，不代表每一条都是可用余额增减。申请提现：可用负、冻结正；确认提现：可用 0、冻结负；驳回：可用正、冻结负。
- `available_delta_minor`、`frozen_delta_minor` 是实际增量；`balance_after_minor` 是当时可用余额。
- 已有历史冻结快照、旧活动配置快照、未知提现精度保持 NULL，不拿当前配置伪造历史。
- 原业务事件和 `wallet.ledger.committed` 都可能出现。钱包事件用于刷新/对账，不能再次发奖或重复计算入账。
- 币种代码/精度及钱包所属用户/币种不可改。需要新的计价单位时创建新币种，不能直接重新解释旧余额。
- 币种开关目前控制目录展示、注册初始化、后台新上分和新链上提现；已有活动、投注和到账义务有各自的启停规则。不是全平台紧急停机开关。

## 执行与恢复要求

1. 先在独立环境演练并备份。检查当前 schema_migrations，不能把已有库当空库重跑旧迁移；特别是旧的 0038/0040/0041 含清理初始化数据的逻辑。
2. 核对所有现存币种代码和真实计价单位。0044 只初始化八种默认币种；自定义币种必须在 0047 前明确登记精度。0047 遇到未知代码会失败，不猜精度。已应用 0044 后目录存在，可登记缺失币种，再续跑；不可为绕过错误批量修改币种或余额。
3. 核对旧积分/体力流水都有对应钱包，且合并后唯一业务键不冲突。0045 在缺钱包或冲突时失败，整个文件回滚。
4. 维护窗口停止 API、Worker、Realtime 后，再执行迁移。0045 会移除旧表，不能与旧版本程序滚动混跑。迁移脚本每个文件的 DDL、搬迁和版本登记原子提交。
5. 启动相同代码版本的三个进程，检查新接口、钱包余额、上分、投注、结算、提现冻结/解冻、活动领奖和 outbox。
6. 回滚不是仅回退二进制：旧版本仍依赖旧表，必须同时恢复迁移前数据库备份并核对维护窗口后的外部到账情况。

0045 删除旧表的源记录已经搬入 ledger_entries；签到明细表不再保留，历史奖励流水仍保留。恢复旧表结构需要迁移前备份。本次只在隔离临时测试库执行了迁移。

## 尚未覆盖的后续改造

本次完成数据库结构和对应核心读写链路，**并非所有接口重设计已完成**：

- 投注、提现、红包、活动参数等原有 `_minor` 请求仍使用整数；后台上分已接受展示金额字符串。其余写接口统一字符串金额需要逐项修改 Go DTO、OpenAPI 和调用测试，不能只改字段名。
- 游标已用于新的本人统一流水；旧后台报表/投注列表仍保留 limit/offset，不在本次直接改变返回结构。
- 活动配置版本目前用于历史快照，不等同于全量替换 API 已支持乐观锁；币种和排行榜配置已有版本冲突保护。
- 未引入按日统计汇总表或账本分区；需要实际数据量与 EXPLAIN/负载结果再决定，不能据空库宣称性能提升。
